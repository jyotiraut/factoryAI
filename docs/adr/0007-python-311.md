# ADR-0007 — Pin Python 3.11

**Status:** accepted · **Date:** 2026-08-04

## Context

The development machine has Python 3.13.9 installed. Anomalib (ADR-0002) and its PyTorch /
Lightning dependency chain support Python 3.10–3.12; 3.13 wheels are incomplete or absent
across parts of that stack. Airflow's supported-version matrix also trails the latest
release.

## Options considered

1. **Use 3.13 and build missing wheels from source** — slow, fragile, and the failure mode
   is a compiler error inside a transitive dependency during CI.
2. **Pin 3.12** — the newest version Anomalib supports; some ecosystem packages still lag.
3. **Pin 3.11** — broadest wheel availability across PyTorch, Anomalib, Airflow, Evidently
   and DVC simultaneously.

## Decision

Pin **Python 3.11** in `pyproject.toml` (`requires-python = ">=3.11,<3.12"`), in every
Dockerfile base image, and in the CI matrix.

Local development happens either inside the Docker containers or in a 3.11 virtualenv; the
system 3.13 interpreter is not used for this project. `make venv` creates the correct
environment and fails loudly on a wrong interpreter version.

## Consequences

**Positive:** every dependency resolves to a prebuilt wheel; CI is fast and reproducible;
the Docker image and local environment agree.

**Negative:** no 3.12+ language features (notably the improved generics syntax and
`typing.override`); the developer must manage a second interpreter alongside the system
one. Revisit when Anomalib publishes 3.12/3.13 support — this ADR is a candidate for
supersession rather than a permanent position.
